## The Problem

**Given:** An integer array `nums` sorted in non-decreasing order.

**Task:** Remove duplicates in-place so each unique element appears only once. Return the number of unique elements `k`.

**Constraint:** You must modify the array in-place with O(1) extra space. The first `k` elements should contain the unique values in sorted order. Elements beyond index `k-1` don't matter.

**Example:**
```
Input:  nums = [1, 1, 2, 2, 2, 3, 4, 4, 5]
Output: k = 5
After:  nums = [1, 2, 3, 4, 5, _, _, _, _]
        (elements after index 4 can be anything)
```

## The Naive Approach (Don't Do This)

Your first instinct might be:
1. Create a new array or set
2. Add unique elements to it
3. Copy back to original array

```java
// ❌ This uses O(n) extra space
public int removeDuplicates(int[] nums) {
    Set<Integer> unique = new HashSet<>();
    for (int num : nums) {
        unique.add(num);
    }
    // ... copy back
}
```

**Problem:** This violates the O(1) space constraint. We need to work in-place.

## The Elegant Solution: Two Pointers

Here's the beautiful part: because the array is **already sorted**, we can use two pointers to track:
- **`j`**: Position of the last unique element we've found
- **`i`**: Current element we're examining

```java
class Solution {
    public int removeDuplicates(int[] nums) {
        int j = 0;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != nums[j]) {
                nums[++j] = nums[i];
            }
        }
        return j + 1;
    }
}
```

That's it. Just 7 lines of code. But how does it work?

## Breaking Down the Algorithm

Let's trace through step by step with the array `[1, 1, 2, 2, 2, 3, 4, 4, 5]`:

### Step 1: Initialize
```
j = 0 (last position of unique elements)
i = 0 (current element)

[1, 1, 2, 2, 2, 3, 4, 4, 5]
 j
 i
```

### Step 2: Move i forward
```
i = 1
nums[i] = 1, nums[j] = 1

[1, 1, 2, 2, 2, 3, 4, 4, 5]
 j  i

nums[i] == nums[j], so skip (it's a duplicate)
```

### Step 3: Found a new unique element
```
i = 2
nums[i] = 2, nums[j] = 1

[1, 1, 2, 2, 2, 3, 4, 4, 5]
 j     i

nums[i] != nums[j]!
Action: j++ (j becomes 1), then nums[j] = nums[i]

[1, 2, 2, 2, 2, 3, 4, 4, 5]
    j  i
```

### Step 4: Keep skipping duplicates
```
i = 3
nums[i] = 2, nums[j] = 2

[1, 2, 2, 2, 2, 3, 4, 4, 5]
    j     i

nums[i] == nums[j], skip
```

### The Pattern Continues...

Each time `nums[i] != nums[j]`:
1. Increment `j` (move to next unique position)
2. Copy `nums[i]` to `nums[j]`
3. Continue

When loop ends:
- `j` points to the last unique element
- Return `j + 1` (count of unique elements)

## Why This Works

The magic is in understanding what `j` represents:

**`j` always points to the last position where we placed a unique element.**

Think of it as a "write cursor" that only moves forward when we find something new to write.

Since the array is sorted:
- All duplicates are grouped together
- When `nums[i] != nums[j]`, we've definitely found a new unique value
- We can safely overwrite position `j+1` because we've already seen all duplicates of `nums[j]`

## Time & Space Complexity

**Time Complexity: O(n)**
- Single pass through the array with pointer `i`
- Each element visited exactly once

**Space Complexity: O(1)**
- Only using two integer pointers (`i` and `j`)
- Modifying array in-place, no extra data structures

This is optimal. You can't solve this problem faster than O(n) because you must examine every element at least once.

## Common Edge Cases

Test your understanding with these cases:

### Empty Array
```java
nums = []
j = 0, loop never runs
return 0 ✅
```

### Single Element
```java
nums = [1]
j = 0, i = 0
nums[0] == nums[0], skip
return 1 ✅
```

### All Unique
```java
nums = [1, 2, 3, 4, 5]
Every nums[i] != nums[j]
j increments each time
return 5 ✅
```

### All Duplicates
```java
nums = [1, 1, 1, 1, 1]
nums[i] == nums[j] for all i > 0
j never moves
return 1 ✅
```

## The Key Insight

The genius of this solution is realizing that in a sorted array:

**You only need to compare with the last unique element you found, not search through everything you've seen before.**

That's the difference between O(n) and O(n²).

This pattern of maintaining a "write cursor" (`j`) that trails a "read cursor" (`i`) appears constantly in array manipulation problems. Master it once, use it everywhere.
